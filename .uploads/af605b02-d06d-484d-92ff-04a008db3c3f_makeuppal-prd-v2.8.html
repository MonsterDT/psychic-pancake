F21 成分合规扫描引擎

这是 Layer 4 "美妆 Anthropic" Constitutional AI 对齐层的最小可行产品。 通用 AI（Claude/GPT）不懂"烟酰胺浓度超过 5% 可能刺激敏感肌"，也不懂"欧盟 CPNP 备案对成分标注的要求"。妆伴把三大红线（过敏风险 / 成分违规 / 虚假宣称）内嵌到产品体验中，从 Day 1 就建立"安全对齐"差异化。

Phase 1 目标

成分扫描月活使用率 >30%，违禁成分检出准确率 >95%，为后续"合规审查 API"（B 端 license 产品）积累规则库和案例库。

功能模块

F21.1 成分表 OCR 识别

  • 用户拍摄产品外包装成分表，或从相册上传成分表图片
  • OCR 识别成分名称（支持中英文、INCI 名、俗名多路匹配）
  • 自动纠错："烟酰胺" vs "Niacinamide" vs "Vitamin B3" 统一归一
  • 端侧预处理：图片裁剪/透视校正/文字区域检测（降低云端 OCR 成本）

F21.2 违禁成分检测（规则引擎）

  • 中国法规库：《化妆品禁用组分》2021 版（1288 种）+ 《化妆品准用防腐剂》+ 《化妆品准用防晒剂》
  • 欧盟法规库：REACH 限制物质 + CPNP 备案要求 + SCCS 评估意见
  • 美国法规库：FDA 21 CFR 700-740（可选，Y2 后接入）
  • 检测结果分级：红色（禁用） / 橙色（限用/需标注）/ 黄色（敏感肌慎用）/ 绿色（安全）
  • 每个命中成分给出：法规依据 + 限量要求 + 风险提示 + 替代建议

F21.3 敏感肌风险评估

  • 基于用户 Layer 3 面部资产库中的肤质标签（敏感肌/油皮/干皮/混合）
  • 成分-肤质冲突矩阵：香精 + 敏感肌 = 高风险；酒精 + 干皮 = 中风险
  • 输出"个人化风险评分"（0-100），并给出"建议皮试区域"（耳后/手腕）
  • 与 F8 "产品防踩雷"打通：成分扫描结果自动写入产品评价的风险标签

F21.4 历史扫描记录

  • 我的扫描历史：按时间轴展示所有扫描过的产品
  • 风险趋势：用户近期扫描产品的平均风险评分变化曲线
  • 一键分享：生成"成分安全报告"卡片（可分享至微信/小红书）

F22 面部与手法物理量采集系统

Day-1 钩子 A。 没有这三条物理量数据，妆伴就只是一个"滤镜 App"；有了它们，才是"美妆物理 AI 基座"。投资人在 A 轮会问"你家跟 Glow Up 差哪"——就指着这三行代码答。

核心原则

物理量采集不增加用户感知成本——在现有面部扫描和教程拆解流程中"静默采集"，用户无额外操作。Day 1 多 20% 开发工作量，换取后续基座叙事的合理性。

三件套物理量

① face_vectors — 面部几何物理量

采集时机：用户每次进行面部扫描（F1 面部资产库）时自动记录

字段类型说明用途
bone_landmarksJSON Array[468]468 个面部关键点坐标（基于 HMS AR Engine）骨相分析 / 模板匹配 / aging 曲线
eye_fissure_angleFLOAT眼裂角度（内眦-外眦连线与水平线夹角）眼妆画法个性化推荐
zygomatic_protrusionFLOAT颧骨突度（mm，基于深度图）修容区域与力度推荐
skin_reflectanceFLOAT[3]肤色反射率（R/G/B 通道）粉底色号精准匹配
face_aspect_ratioFLOAT面宽/面长比脸型分类（圆脸/长脸/方脸）
nose_bridge_heightFLOAT鼻梁高度（mm）鼻影打法推荐

② steps[n].parameters — 手法物理量

采集时机：创作者在 Creator Pro（F4）拆解教程时，系统自动提取；或用户跟着镜面模式（F6）实操时，通过端侧推理估算

字段类型说明用途
brush_landing_pctFLOAT刷子落点百分比（相对面部区域，如"眼尾 30% 处"）精准复刻 / 机器人可执行
brush_radius_mmFLOAT刷子接触半径（mm）晕染范围控制
pressure_levelINT (1-5)力度等级（轻扫/按压/点拍等）上色浓度控制
stroke_direction_degFLOAT走向角（0-360度，如眉笔"45度上扬"）线条走向教学
layer_countINT叠加层数妆效浓淡控制
dwell_time_msINT停留时间（ms，如遮瑕点拍停留 200ms）遮瑕/定妆手法

③ product_physics — 产品物理属性

采集时机：用户通过 F15 美妆工具箱扫码添加产品，或品牌方在 F23 品牌中心录入产品时填写

字段类型说明用途
pearl_particle_size_umFLOAT珠光粒径（微米）光泽度模拟 / PBR 渲染
adhesion_scoreFLOAT (0-1)附着度（持妆能力）妆效持久性预测
blendability_scoreFLOAT (0-1)晕染度（易推开程度）手法难度评估
undertoneENUM底色（Warm/Neutral/Cool）肤色匹配
coverage_levelINT (1-5)遮盖力遮瑕需求匹配
finish_typeENUM妆效（Matte/Dewy/Satin/Velvet）风格推荐

数据采集架构

隐私合规

原始图像永不出端；云端只存储特征向量（128-dim float 数组）和物理量数值。符合 PIPL 最小必要原则，已通过等保二级预审。

F23 品牌方合作与数据回流中心

Day-1 钩子 B + B 端现金牛入口。 Phase 1 的目标是拿 2-3 家 Top 集团联合实验室意向，做"配方生成 + 成分合规 + 虚拟试妆"三件套 license 试点。F23 是品牌方接触妆伴的第一站，也是数据回流协议签署的系统化载体。

Phase 1 目标

签约 2-3 家品牌联合实验室意向，品牌白标模板 10+，数据回流协议签署率 100%（所有合作品牌必须签署）。

功能模块

F23.1 品牌官方入驻

  • 品牌入驻申请：提交营业执照 + 品牌授权书 + 联系人信息
  • 平台审核：3 个工作日内完成资质审核
  • 品牌主页：Logo + 品牌故事 + 官方妆容模板 + 产品清单 + 活动公告
  • 蓝 V 认证标识：在 C 端展示"官方认证"标签

F23.2 白标模板众包发布

  • 品牌方在 Creator Pro（F4）中创建"品牌专属模板"，标记为"官方白标"
  • 模板审核：平台审核内容合规性（无虚假宣传 / 功效宣称有备案支撑）
  • C 端展示：品牌模板在「妆容商城」（F13）中置顶，带"官方"角标
  • 收益分成：品牌模板解锁收入，品牌方 50% / 创作者 30% / 平台 20%（若创作者参与）或品牌方 70% / 平台 30%（纯官方模板）

F23.3 数据回流协议签署

  • 协议模板：平台提供标准化"数据联合实验室合作协议"，包含数据范围、使用目的、脱敏要求、所有权归属、终止条款
  • 数据范围：
    • 品牌方提供：配方实验参数 + 消费者复购行为 + 肤测反馈数据
    • 妆伴提供：模板解锁率 + 用户评分 + 肤质匹配反馈
  • 脱敏要求：所有数据经 k-匿名化处理（k≥5），个人标识符完全去除
  • 所有权：原始数据归品牌方所有；模型改进产生的增量价值由双方按协议分成
  • 电子签署：法大大/e 签宝集成，具备法律效力

F23.4 品牌数据看板（B 端 SaaS）

  • 模板表现：解锁次数 / 完成率 / 用户评分 / 复购转化率
  • 用户画像：使用模板的用户肤质分布 / 年龄段 / 地域分布
  • 成分反馈：用户对产品成分的扫描记录 + 风险反馈统计
  • 竞品对比：同类品牌模板的平均表现（匿名聚合）

F23.5 联合实验室意向申请

  • 品牌方在线提交"联合实验室合作意向书"
  • 选择合作方向：配方生成 AI / 成分合规引擎 / 个性化推荐 / VTO 渲染优化
  • 平台 BD 团队跟进：安排技术对接会 + 数据对接方案
  • 意向确认后进入"联合实验室"专属服务通道

F24 焕新值经济系统 2.0

Phase 1 付费转化的核心支撑系统。 V2.7 已建立基础焕新值体系（获取/消耗/90 天过期），V2.8 引入任务体系 + 会员等级 + 兑换商城三驾马车，目标支撑注册转化率 >15%、付费率 >3%。

Phase 1 目标

注册转化率 >15%（Onboarding 漏斗优化 + 任务奖励驱动），月付费率 >3%（等级权益 + 兑换稀缺性），焕新值日活使用率 >60%。

兑换机制

  • 限量机制：品牌小样每日限量 100 份，营造稀缺感
  • 等级门槛：高价值实物仅限 Lv.3+ 兑换（激励升级）
  • 物流对接：小样/实物由品牌方或平台仓库直发，物流信息同步至 App
  • 防刷机制：同一地址/手机号 7 天内限兑 1 次；异常 GP 获取行为触发风控冻结

焕新值经济闭环

防刷与风控

  • 行为检测：同一设备/账号短时间内异常高频完成任务，触发验证码 + 人工复核
  • 设备指纹：建立设备唯一标识，识别多账号同设备刷量
  • 社交验证：分享类任务要求被分享方真实互动（打开链接 + 停留 >10s）
  • GP 冻结期：通过邀请获得的 GP 冻结 7 天（防止邀请后秒注销）
  • 黑名单：确认作弊账号 GP 清零 + 封号 + 设备拉黑

新增数据模型

F21 成分合规相关

-- 成分扫描记录
CREATE TABLE ingredient_scan (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id         BIGINT NOT NULL,
  product_name    VARCHAR(255),
  product_image   VARCHAR(500),
  ocr_raw_text    TEXT,
  parsed_ingredients JSON,
  risk_score      INT DEFAULT 0,
  risk_level      ENUM('safe','caution','warning','danger') DEFAULT 'safe',
  skin_type_match JSON,
  scan_source     ENUM('camera','album') DEFAULT 'camera',
  created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id),
  INDEX idx_created_at (created_at)
);

-- 合规规则库
CREATE TABLE compliance_rule (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  ingredient_name VARCHAR(255) NOT NULL,
  ingredient_inci VARCHAR(255),
  region          ENUM('CN','EU','US') DEFAULT 'CN',
  rule_type       ENUM('banned','restricted','caution') NOT NULL,
  max_concentration DECIMAL(5,2),
  restriction_desc TEXT,
  source_regulation VARCHAR(255),
  effective_date  DATE,
  version         INT DEFAULT 1,
  INDEX idx_ingredient (ingredient_name),
  INDEX idx_region_type (region, rule_type)
);

-- 肤质-成分冲突矩阵
CREATE TABLE skin_ingredient_conflict (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  ingredient_id   BIGINT NOT NULL,
  skin_type       ENUM('sensitive','oily','dry','combination') NOT NULL,
  risk_level      ENUM('low','medium','high') NOT NULL,
  advice_text     VARCHAR(500),
  UNIQUE KEY uk_ingredient_skin (ingredient_id, skin_type)
);
